Performance Analysis — Fog of War at SC2 Speed

SC2 Faster = 22.4 fps. Every design choice below is held to that budget.

Visibility computation — negligible

Work per tick
  • ~15 friendly observers (units + buildings)
  • Vision radius 8–10 → ~260 tiles per observer
  • ~3,900 tile checks: distance float + height lookup
  • Filter ~20 enemy units through isVisible()
Estimate
~0.05ms
per tick. Budget is 44ms at 22.4fps.
No concern here.

WebSocket payload — needs compact encoding

64×64 = 4,096 tiles. How we encode matters:

Encoding Size/frame @ 22.4fps Verdict
int[64][64] JSON array ~12 KB ~270 KB/s Workable but heavy
String of 4096 chars ('0'/'1'/'2') ~4 KB ~90 KB/s ✓ Recommended
Delta (changed tiles only) ~0.1 KB ~2 KB/s Overkill for local

Flat string: "0002211..." — 4096 chars. JS reads it as vis.charAt(y*64+x). Simple, compact, no parsing overhead. Local WebSocket handles 90KB/s trivially.

Visualizer rendering — requires careful PixiJS approach

The real risk: 4,096 individual PixiJS sprites updated each frame would tank performance. We must use a single-pass batch draw.
Approach: One PIXI.Graphics object for the fog layer, redrawn each frame:
fogLayer.clear();
// Single pass — PixiJS batches all rect draws
for (let y = 0; y < 64; y++) {
  for (let x = 0; x < 64; x++) {
    const s = vis.charAt(y*64+x);
    if (s === '2') continue; // VISIBLE — no fog
    fogLayer.rect(x*TILE, yFlip(y)*TILE, TILE, TILE)
      .fill({ color: 0x000000, alpha: s==='0' ? 1.0 : 0.6 });
  }
}

4,096 batched rect calls in PixiJS 8 — well within 44ms budget. PixiJS submits as a single GPU draw call.
